# 등기 포털 보안 — 위협별 대응표와 운영자 점검표

대상: 가비아 공유호스팅의 PHP 8 등기 포털 (손님 조회 + 직원 관리자).
국내 PHP 사이트 침해의 주된 경로를 기준으로, 무엇을 막았고 무엇이 남았는지 적는다.
구현 상세는 README 「4단계」 절, 전환 절차는 CUTOVER.md.

## 1. 위협별 대응표

### 1-1. 파일 업로드 웹쉘 (가장 흔한 침해 경로)

| 공격 | 막는 장치 |
|---|---|
| 엑셀 대신 `.php` 를 올림 | 확장자 `.xlsx` 만 허용 (`app/upload.php`) |
| `shell.php.xlsx` 처럼 이름 위장 | 이름 중간의 실행 확장자도 거부 |
| 내용만 PHP 인 `.xlsx` | 내용 기준 MIME(finfo) + ZIP 시그니처 `PK\x03\x04` + xlsx 내부 구조 검사 |
| ZIP 안에 PHP 를 숨김 · zip 폭탄 | ZIP 항목에 실행 확장자·`..` 경로가 있으면 거부, 압축률 200배 초과·해제 합계 100MB 초과 거부 |
| 올린 파일을 웹에서 실행 | 웹루트 밖 임시폴더에 무작위 이름으로만 저장, 파싱 직후 삭제. 웹루트에는 업로드 파일이 남지 않는다 |
| 어떻게든 웹루트에 PHP 가 생김 | `public/.htaccess` 가 index.php 외 PHP 실행을 막는다. `app/`·`tools/` 는 웹에서 전부 거부 |
| 몰래 심긴 파일·고친 코드 | `tools/integrity.php` 가 HMAC 서명된 기준선과 대조, 웹루트의 새 PHP 는 「웹쉘 의심」으로 표시. 크론이 매시간 대조하고 이상하면 HTTP 500 → 메일 |

### 1-2. 관리자 계정 탈취

| 공격 | 막는 장치 |
|---|---|
| 비밀번호 유출·추측 | argon2id 해시, 5회 실패 15분 잠금, **OTP 2단계 필수** (RFC 6238) |
| 비밀번호만 훔쳐 OTP 를 자기 휴대폰에 등록 | 첫 등록·초기화 후 재등록은 admin 이 발급한 1회용 등록코드(24시간)가 있어야 비밀키가 열린다 |
| OTP 6자리 무차별 대입 | 계정 단위 5회 실패 → 15분 잠금 (비밀번호를 다시 넣어도 유지) + IP 차단 원장 |
| 화면을 엿본 OTP 코드 재사용 | 통과한 30초 단계를 기록해 같은 코드(이전 단계 포함) 재사용 거부 |
| 휴대폰 분실 | 복구코드 8개(해시 저장·1회용), admin 의 OTP 초기화(작업기록) |
| 밖에서 관리자 화면 접속 | 관리자 IP 허용목록 — 목록 밖이면 로그인 화면도 403. 지금 IP 가 빠진 목록은 저장 거부(자기 잠금 방지), DB 오류 시 닫힘 |
| 퇴사·권한 변경 후에도 열린 세션 | 매 요청 DB 와 대조: 중지·비밀번호 재설정·OTP 초기화(auth_version)면 즉시 끊고, 권한이 바뀌면 세션 재발급 |
| 로그인된 PC 를 다른 사람이 만짐 | 유휴 30분·절대 9시간 만료, CSV 내보내기·개인정보 「보기」·세대 수정·직원계정 관리·보안 설정은 최근 10분 OTP 재확인 |

### 1-3. 명단 기반 무차별 대입 (손님 조회)

이름·생년월일·동호는 분양 명단이 새면 함께 새는 정보라 그것만으로는 본인 확인이 약하다.

| 공격 | 막는 장치 |
|---|---|
| 유출 명단으로 남의 세대 조회 | **문자 인증 2단계** — 그 명의인의 등록 휴대폰으로 6자리. 휴대폰이 없는 세대는 등기센터 안내로 막는다 |
| 한 세대에 생년월일 대입 | 세대 기준 1시간 10회 실패 → 잠금 |
| 여러 세대를 돌아가며 대입 | IP 단위: 10분에 서로 다른 대상 5곳 또는 30회 실패 → 1시간 차단 (IPv6 는 /64 단위). 손님·문자·직원·OTP 실패를 한 원장(`login_log.kind`)으로 센다 |
| 인증번호 대입 | 코드당 5회(동시 요청도 원자적 예약으로 정확히 5회), 3분 만료, 코드는 HMAC 해시로만 저장 |
| 문자 폭탄(남의 휴대폰으로 계속 발송) | 재발송 60초 간격·명의인당 시간당 5회(명의인 단위 잠금으로 동시 요청도 직렬화), IP 차단 중에는 발송도 멈춤 |

### 1-4. 세션 탈취

| 공격 | 막는 장치 |
|---|---|
| XSS 로 쿠키 탈취 | 모든 출력 `h()` 이스케이프 + CSP(`script-src 'self' 'nonce-…'`, 인라인 핸들러 없음) + HttpOnly 쿠키 |
| 다른 사이트에서 요청 위조(CSRF) | 전 POST CSRF 토큰 + SameSite=Strict + `form-action 'self'` |
| 평문 구간 도청 | 운영은 https 강제(301), HSTS, Secure·`__Host-` 쿠키 |
| 세션 고정 | strict mode, 로그인·재인증·권한 변경 때 세션ID 재발급 |
| 훔친 쿠키를 다른 브라우저에서 사용 | 세션을 브라우저(UA) 지문에 묶어 바뀌면 통째로 폐기 |
| 공용 PC 에 남은 화면 | 유휴 손님 10분/직원 30분, 절대 2시간/9시간, `Cache-Control: no-store` |
| 클릭재킹 | `X-Frame-Options: DENY` + `frame-ancestors 'none'` |

### 1-5. DB 유출 (SQL 인젝션·호스팅 사고·백업 유출)

| 공격 | 막는 장치 |
|---|---|
| SQL 인젝션 | 전 쿼리 prepared statement (진짜 prepare, 에뮬레이션 끔) |
| DB 덤프가 통째로 새도 | 주소·계좌·OTP 비밀키는 sodium 암호화(키는 설정 파일에만). 비밀번호·복구코드·등록코드·인증번호는 해시만 |
| 백업 파일 유출 | 백업은 별도 키(backup_key)로 XChaCha20-Poly1305 암호화, 웹루트 밖 보관, 1바이트만 바뀌어도 복원 거부 |
| 개발 키로 운영 | env=prod 에서 개발 키(지문 대조)·개발 문자 드라이버면 부팅 거부 |
| 직원의 과도한 열람 | 목록은 기본 마스킹, 원문 「보기」·CSV·주소/환불 열람은 전부 `staff_audit` |

### 1-6. 관리자 PC 감염 (키로거·원격제어·브라우저 쿠키 탈취)

앱만으로 완전히 막을 수 없는 영역이다. 피해를 줄이는 장치:

| 위험 | 줄이는 장치 / 남는 위험 |
|---|---|
| 비밀번호를 키로거로 훔침 | OTP 가 휴대폰에 있어 비밀번호만으로는 못 들어온다 |
| 감염 PC 의 열린 세션을 원격으로 사용 | IP 허용목록(사무실 밖에서 못 씀), 민감 작업 10분 OTP 재확인, 유휴 30분. **같은 PC 에서 원격 조종되면 막지 못한다** — 백신·업데이트가 필수 |
| 엑셀·CSV 파일이 PC 에 쌓임 | CSV 는 OTP 재확인 후에만 나간다. 내려받은 파일 정리는 직원 몫 |
| FTP 비밀번호 탈취 → 코드 변조 | SFTP 사용, 무결성 크론이 변경을 잡는다 |

## 2. 남은 위험 (알고 쓰는 것)

- **문자 업체 미정** — 알리고·솔라피는 요청 형식까지만 만든 스텁(`live=false`). 계약 후 응답 판정을 실제 문서로 보강하고 실발송 시험이 필요하다. 그 전까지 운영에서 손님 로그인은 안 된다.
- 휴대폰이 없거나 바뀐 세대는 조회할 수 없다 — 등기센터가 연락처를 보강해야 한다.
- 문자 인증은 유심 복제·문자 가로채기에는 약하다(국내 일반 수준). 계좌 변경은 재인증 + 작업기록으로 사후 추적.
- 손님 유휴 10분은 긴 설문을 쓰다 끊길 수 있다(제출 시 로그인 화면으로). 불편 신고가 있으면 늘린다.
- 같은 사무실 NAT 뒤에서 손님 실패가 몰리면 그 IP 가 1시간 막힐 수 있다 — 허용목록 IP 는 직원 로그인에서 제외되고, admin 이 보안 설정에서 해제할 수 있다.
- CSP 는 `style=""` 속성을 허용한다(기존 화면 159곳). 스크립트 실행은 막혀 있고, `<style>` 요소는 막혀 있다.
- 웹폰트 CSS·글꼴은 cdn.jsdelivr.net 에서 받는다(CSP 허용). 필요하면 assets 로 옮겨 CSP 를 self 로 좁힌다.
- 무결성 기준선 파일과 백업은 같은 계정 디스크에 있다 — 호스팅 계정이 통째로 털리면 함께 위험. 백업은 주기적으로 서버 밖(대표 PC 등)에도 받아 둔다.

## 3. 운영자 점검표

### 매일 (자동)
- [ ] `/cron/backup` 성공 메일 없음 = 정상 (실패 시 메일). backup_dir 에 최근 파일이 있는지 주 1회 눈으로 확인
- [ ] `/cron/integrity` 실패 메일이 오면 **즉시** 개발 담당에게 연락 — 「웹쉘 의심」 줄의 파일을 지우기 전에 사본 보존

### 매주
- [ ] 관리자 → 보안 설정: 자동 차단 IP 목록 (같은 IP 가 반복되면 기록)
- [ ] 접속 통계 → 조회 실패·잠금: 특정 단지에 실패가 몰리는지
- [ ] 접속 통계 → 직원 작업기록: `*.reveal`·`export.csv`·`staff.otp_reset` 이 업무와 맞는지

### 매월
- [ ] **가비아 PHP 버전 최신 유지** — 호스팅 관리에서 PHP 8.x 최신 보안 판으로 (지원 끝난 버전 금지)
- [ ] 직원 명단과 계정 대조 — 퇴사·휴직자는 즉시 「중지」, 복구코드 남은 수 확인
- [ ] 백업 파일 하나를 로컬로 받아 `restore.php --decrypt-to` 로 풀리는지 확인 (분기 1회 이상)
- [ ] 관리자 IP 허용목록이 지금 사무실 IP 와 맞는지

### 접속·PC 수칙
- [ ] 파일 올리기는 **FTP 대신 SFTP** (가비아 SFTP 사용, FTP 계정은 끄거나 비밀번호를 길게)
- [ ] **관리자 PC 백신** 실시간 감시 켜기 + Windows 자동 업데이트 + 브라우저 최신
- [ ] 관리자 화면은 업무 PC 에서만, 공용·개인 PC·PC방 금지
- [ ] 비밀번호·OTP 비밀키·등록코드·복구코드를 메신저·메일·사진으로 주고받지 않는다
- [ ] 휴대폰 분실 즉시 admin 에게 OTP 초기화 요청
- [ ] crypto_key·backup_key·cron_token 은 설정 파일에만, 사본은 서버 밖 안전한 곳. 유출이 의심되면 cron_token 은 바로 교체(키 교체는 개발 담당과 재암호화 절차 필요)

### 코드 배포 때마다
- [ ] `php -l` 통과본만 올린다 → 올린 뒤 `tools/integrity.php baseline` 다시 만든다
- [ ] 운영 설정에 `session_timeouts`·`sms_driver => 'dev'` 가 없는지 (있으면 503 — 앱이 막는다)
